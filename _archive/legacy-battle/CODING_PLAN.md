# 낱말탑 CODING_PLAN

원칙: 마일스톤 1개 = 한 세션(2~3시간). 끝날 때마다 **실행해서 눈으로 확인 가능한 결과물** + git 커밋 + `/clear`.

---

## 1. 기술 스택 확정

### 프레임워크: 없음 (순수 JS)
- 화면이 4개뿐이고 상태도 객체 하나면 충분해서 프레임워크가 해결해줄 문제가 없다
- 대안 React: CDN으로 붙이면 Babel 변환 때문에 첫 로딩이 느려지고, 빌드를 붙이면 학생 배포가 복잡해진다
- 유지보수: 순수 JS라 어떤 파일을 열어도 그 자리에서 읽힌다. 형이 반년 뒤 열어도 추적 가능

### 파일 구조: 여러 파일 + 전역 상수 로딩
- 카드 데이터가 60장까지 늘어나므로 단일 HTML은 곧 2000줄이 된다
- 대안 ES module: `file://`에서 CORS로 막힌다. USB로 복사해 쓰는 시나리오가 죽는다
- 유지보수: `<script src>`를 순서대로 나열하는 방식이라 규칙이 단순하다

### 저장: localStorage
- 저장할 게 '진행 중인 런 + 최고 층수'뿐이고 학생별 데이터를 모을 계획이 없다
- 대안 서버/Supabase: 학생 데이터를 서버로 보내는 순간 동의·보관 문제가 생긴다. 얻는 게 없다
- 유지보수: 브라우저 개발자도구에서 바로 들여다보고 지울 수 있다

### 빌드: 없음
- `index.html`을 더블클릭하면 그게 곧 실행이다. 교실에서 제일 강한 조건
- 대안 Vite: 개발은 편하지만 배포마다 빌드 단계가 끼고, 학생 기기에서 문제 생기면 원인이 두 배로 늘어난다
- 유지보수: 배포 = 폴더 복사. 실패할 부분이 없다

## M1. 빈 앱 띄우기
목표: 게임 로직 없이 **화면이 전환되는 껍데기**까지만.

- 폴더 구조 전부 생성 (`css/`, `js/`, 빈 데이터 파일 포함)
- `index.html`에 화면 4개를 `<section>`으로 두고 하나만 보이게 (`.screen.active`)
- `js/ui.js`에 `showScreen(name)` 함수 하나
- 시작 화면: 제목 "낱말탑", [새 게임] 버튼
- 전투/보상/맵 화면은 회색 박스에 이름만

**완료 조건**
- [ ] `index.html` 더블클릭으로 열린다
- [ ] [새 게임]을 누르면 전투 화면(회색 박스)으로 바뀐다
- [ ] 콘솔에 에러가 없다

---

## M2. 카드 데이터 + 손패 뽑기
목표: 덱에서 카드를 뽑아 화면에 보여주기. 아직 낼 수는 없다.

- `js/data-cards.js`에 카드 12장 (`docs/카드-초안.md` 참조)
- `js/data-enemies.js`에 괴물 2종
- `js/state.js`: `gameState` 객체 정의 — 덱 / 손패 / 버린 더미 / 집중력 / 생각
- 셔플, 5장 드로우, 덱 소진 시 버린 더미 재셔플
- `js/ui.js`: 손패 카드 렌더링 (낱말, 뜻, 비용, 공격력)

**완료 조건**
- [ ] 전투 화면에 손패 5장이 뜬다
- [ ] 새로고침할 때마다 순서가 달라진다
- [ ] 덱을 다 뽑으면 버린 더미가 다시 섞여 들어온다 (콘솔로 확인)

---

## M3. 전투 루프
목표: 전투 한 판을 이기거나 질 수 있다. 이 마일스톤이 게임의 심장이다.

- 괴물이 요구 문장 + 조건 태그를 표시
- 카드 클릭 → 생각(에너지) 차감 → `matches(card, demand)` 판정
- 정타: 공격력만큼 / 빗나감: 절반 + 낱말 뜻 한 줄 설명
- [턴 종료] → 괴물 공격 → 집중력 차감 → 손패 버리고 5장 재드로우
- 괴물 HP 0 → 승리 메시지 / 집중력 0 → 패배 메시지
- 카드 부가 효과는 `draw1` 하나만 먼저 구현. 나머지는 M6

**완료 조건**
- [ ] 카드를 내면 괴물 체력이 줄어든다
- [ ] 조건에 맞는 카드와 안 맞는 카드의 결과가 명확히 다르다
- [ ] 빗나갔을 때 낱말 뜻 설명이 뜬다 (실패를 나무라는 문구 금지)
- [ ] 생각이 부족하면 카드가 눌리지 않고, [턴 종료]가 강조된다
- [ ] 승리·패배가 모두 재현된다

---

## M4. 보상 + 덱 성장
목표: 전투를 연달아 하면서 덱이 실제로 변한다.

- 승리 후 카드 3장 랜덤 제시 → [이 카드 받기] / [안 받기]
- 선택한 카드가 다음 전투 덱에 실제로 들어간다
- [덱 보기] 모달: 현재 덱 전체, 같은 카드는 `×2`로 묶음

**완료 조건**
- [ ] 2연전을 하면 덱이 10장 → 11장이 된다
- [ ] [안 받기]가 정상 동작하고, 덱 크기가 그대로다
- [ ] 덱 보기에서 방금 받은 카드가 보인다

---

## M5. 맵 + 런 종료 + 저장
목표: 1층부터 보스까지 한 판을 완주하고, 껐다 켜도 이어진다.

- 세로 맵 15층, 노드 3종: 전투 / 휴식(집중력 회복) / 보스(5·10·15층)
- 집중력 0 → 결과 화면: 도달 층수, 최고 기록 갱신
- localStorage 저장: 층·덱·집중력. 매 노드 종료 시 저장
- 저장 데이터가 깨졌으면 조용히 초기화

**완료 조건**
- [ ] 1층부터 15층 보스까지 완주 가능하다
- [ ] 전투 중 브라우저를 껐다 켜면 [이어하기]가 뜬다
- [ ] localStorage를 손으로 망가뜨려도 앱이 죽지 않는다

---

## M6. 콘텐츠 채우기
목표: 게임이 아니라 **교재**가 되는 단계. 코딩보다 낱말 고르는 시간이 길다.

- 카드 60장까지 확장 (속담 20 / 관용구 20 / 한자어 10 / 고유어 10)
- 괴물 12종, 각 괴물마다 요구 문장 3개 이상
- 나머지 카드 효과 구현: `block4`, `energy1`
- 6학년 교육과정 밖 어휘가 섞이지 않았는지 형이 직접 검수

**완료 조건**
- [ ] 카드 60장, 괴물 12종
- [ ] 같은 층을 두 번 해도 문장이 겹치지 않는다
- [ ] 형이 카드 목록을 처음부터 끝까지 읽고 승인했다

---

## M7. 디자인 입히기
목표: 회색 박스를 걷어낸다. 기능이 다 된 뒤에 하는 게 맞다.

- 도트·파스텔 방향, Galmuri 폰트
- 카드 사용 / 피격 / 승리 애니메이션 (CSS만)
- 태블릿 세로 대응: 손패 2줄 접기
- 첫 실행 튜토리얼 3단계 (20초 안에 끝날 것)
- 효과음 (선택)

**완료 조건**
- [ ] 태블릿 세로에서 가로 스크롤이 생기지 않는다
- [ ] 처음 켠 학생이 튜토리얼만 보고 첫 카드를 낸다

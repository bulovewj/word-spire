# 낱말탑 작업지시서

## 0. 한 줄 정의
초등 6학년 학생을 위해, 낱말 카드로 덱을 짜서 문장 괴물을 이기며 탑을 오르는 덱빌딩 게임.

## 1. 게임 규칙 (설계의 핵심)

### 1-1. 왜 덱빌딩인가
단어를 많이 아는 것보다 상황에 맞게 쓰는 것이 문해력이다.
덱빌딩은 이 메시지를 규칙 자체로 전달한다 — 카드를 무조건 다 주우면 덱이 뚱뚱해져서 정작 필요한 카드가 손에 안 잡힌다.
**보상 화면에서 "안 받기"를 반드시 선택 가능하게 할 것.** 이게 이 게임의 교육적 핵심이다.

### 1-2. 자원
| 자원 | 게임 안 이름 | 설명 |
|---|---|---|
| 체력 | 집중력 | 30에서 시작. 0이 되면 런 종료 |
| 에너지 | 생각 | 매 턴 3으로 회복. 카드 비용으로 소모 |
| 덱 | 낱말 주머니 | 기본 10장으로 시작 |

### 1-3. 전투 흐름
1. 문장 괴물이 **상황**과 **요구 태그**를 함께 보여준다. 빈칸은 쓰지 않는다.
   - 상황: "숙제? 내일 하지 뭐. 내일도 있고 모레도 있고…"
   - 요구: `[게으름] [뒤늦음]`
2. 플레이어는 손패 5장에서 카드를 낸다. 에너지가 허락하는 만큼 여러 장 가능.
3. 판정 3단계 — **정답은 하나가 아니다.**

   | 판정 | 조건 | 데미지 |
   |---|---|---|
   | 정타 | 태그 겹침 + `type === bestType` | power × 1.5 |
   | 통함 | 태그만 겹침 | power × 1.0 |
   | 빗나감 | 태그 안 겹침 | power × 0.3 + 낱말 뜻 설명 |

4. 턴 종료 → 괴물이 공격 (집중력 감소) → 손패 버리고 5장 새로 뽑기
5. 괴물 체력 0 → 승리 → 보상 화면

**왜 빈칸을 안 쓰나**: 빈칸은 정답이 하나라 손패에 그 카드가 없으면 턴이 죽는다.
상황 + 태그 방식은 통하는 카드가 여러 장이라 낼 수 없는 턴이 생기지 않는다.
언어의 실제 모습에도 더 가깝다 — 한 상황을 나타내는 말은 여럿이고, 그중 딱 맞는 것이 있을 뿐이다.

### 1-4. 코스트 = 태그 폭 (밸런스의 핵심)
강한 카드에 별도 페널티를 붙이지 않는다. **태그 개수 자체가 페널티다.**

| 코스트 | 태그 수 | 힘 | 성격 |
|---|---|---|---|
| 0 | 3 | 3~4 | 아무 데나 통함, 약함 |
| 1 | 3 | 5~6 | 무난 |
| 2 | 2 | 9~11 | 조건이 붙음 |
| 3 | 1 | 14~16 | 딱 그 상황만. 손에서 썩는 게 정상 |

`어물전 망신은 꼴뚜기가 시킨다`(코스트3, 태그 `[곤란]` 하나, 힘 16)는 그 태그를 요구하는 괴물이
나올 때까지 쓸 수 없다. 획득도 tier 3(11~15층)으로 막혀 있다.
여기서 덱 압축 압력이 나온다 — 센 카드만 주워담으면 손패 다섯 장이 전부 못 쓰는 카드가 된다.

### 1-5. 오답 처리 원칙
틀렸을 때 화면을 붉게 물들이거나 "틀렸습니다"를 띄우지 말 것.
데미지가 약하게 들어가고, 그 낱말의 뜻과 왜 이 상황에 안 어울리는지가 한 줄로 뜬다.
**실패도 진행이다.** 빗나가도 데미지가 들어가므로 낼 카드가 없는 턴은 존재하지 않는다.

### 1-6. 보상
전투 승리 시 카드 3장 제시 → 1장 선택 또는 **안 받기**.
집중력 회복은 별도 노드(휴식)에서만.
제시 풀은 현재 층의 tier 이하 카드로 한정한다.

## 2. 데이터 스키마

### 태그 16종 (고정. 늘리지 말 것)
```
게으름 뒤늦음 노력 협동 인간관계 혼란 교만 거짓
욕심 좁은시야 걱정 조심 성급함 소문 곤란 결과
```
태그를 늘리면 요구 하나당 통하는 카드가 줄어 손패가 막힌다.
현재 요구당 통하는 카드는 평균 16장(60장 중), 최소 7장.
시작 덱 10장 기준으로 손패 5장에 통하는 카드가 최소 한 장 나올 확률은 78~100%.

### 낱말 카드
```js
{
  id:"c01", word:"우물 안 개구리", type:"속담",   // 속담|관용구|한자어|고유어
  cost:1, power:6, tags:["좁은시야","교만","혼란"],
  tier:1,              // 1: 1~5층 보상 / 2: 6~10층 / 3: 11~15층
  start:true,          // 시작 덱 10장 여부
  effect:"draw1",      // "draw1"|"block4"|"energy1"|없음
  meaning:"넓은 세상을 모르고 자기 생각만 옳다고 여기는 사람",
  example:"책만 보고 여행을 안 하면 우물 안 개구리가 되기 쉽다."
}
```

### 문장 괴물
```js
{
  id:"e01", name:"어영부영 게으름뱅이", hp:20, attack:4, tier:1,
  boss:false,
  demands:[
    { situation:"숙제? 내일 하지 뭐. 내일도 있고 모레도 있고…",
      ask:"이 모습을 뭐라고 할까?",
      accept:["게으름","뒤늦음"],   // 하나라도 겹치면 통함
      bestType:"고유어" }           // 여기까지 맞으면 정타. null이면 종류 무관
  ]
}
```
**새 요구를 추가할 때 `accept`는 반드시 2태그로 잡는다.** 1태그 요구는 보스에만 쓴다.

### 구성 현황
- 카드 60장: 속담 20 / 관용구 20 / 한자어 10 / 고유어 10
- 코스트 분포: 0코 7장, 1코 24장, 2코 24장, 3코 5장
- tier 분포: 1티어 24장, 2티어 25장, 3티어 11장
- 괴물 12종: 티어별 일반 3 + 보스 1
- 보스 3종은 PISA 인지 과정 대응 — 두더지(정보 찾기) / 꽈배기 뱀(이해하기) / 그럴싸 여우(평가와 성찰)

## 3. 화면

### 화면 A — 시작
- 제목, [새 게임], [이어하기](저장된 런 있을 때만), 최고 기록 표시
- 규칙 설명 3줄 (읽는 데 20초 넘지 않게)

### 화면 B — 전투
- 상단: 괴물 이름, 체력바, 지금 요구하는 문장(빈칸 포함)과 조건 태그
- 중앙: 판정 결과 메시지 영역
- 하단: 손패 5장(가로 스크롤), 집중력 / 생각 / 남은 덱 수
- 버튼: [턴 종료], [덱 보기]

### 화면 C — 보상
- 카드 3장 나란히, 각 카드 뜻과 예문 표시
- [이 카드 받기] / [안 받기]

### 화면 D — 맵 (마일스톤 4)
- 1층부터 위로 올라가는 세로 경로. 노드 종류: 전투 / 휴식 / 보스
- 5층마다 보스. 총 15층이면 한 판 클리어

## 4. 엣지 케이스
- 덱을 다 뽑았을 때 → 버린 카드 더미를 섞어 덱으로 되돌린다
- 손패에 낼 수 있는 카드가 없을 때(에너지 부족) → [턴 종료] 버튼을 강조
- 저장 데이터가 깨졌을 때 → 조용히 초기화하고 시작 화면으로. 오류 코드 노출 금지
- 화면이 좁을 때(태블릿 세로) → 손패를 2줄로 접는다
- 같은 카드를 여러 장 가진 경우 → 덱 보기에서 "×2"로 묶어 표시

## 5. 완성 기준 (체크리스트)
- [ ] 파일을 더블클릭해서 열었을 때(`file://`) 정상 동작한다
- [ ] 전투 한 판을 처음부터 끝까지 진행할 수 있다
- [ ] 조건에 맞는 카드와 안 맞는 카드의 결과가 눈에 띄게 다르다
- [ ] 오답 시 낱말 뜻 설명이 뜬다
- [ ] 보상에서 "안 받기"를 고를 수 있다
- [ ] 덱이 소진되면 버린 더미가 다시 섞인다
- [ ] 브라우저를 껐다 켜도 진행 중인 런을 이어할 수 있다
- [ ] 카드 60장, 괴물 12종이 데이터에 들어 있다
- [ ] 6학년 학생이 설명 없이 3분 안에 규칙을 파악한다 (교실 테스트로 검증)

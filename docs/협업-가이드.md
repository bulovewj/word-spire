# Claude Code × Codex 협업 가이드

같은 저장소를 두 에이전트가 동시에 고치면 서로의 작업을 덮어쓴다. 그래서 **폴더와 브랜치를 나눈다.**
git worktree를 쓰면 한 저장소에서 브랜치마다 폴더를 따로 열 수 있다.

## 폴더 배치

| 누가 | 폴더 | 브랜치 | 하는 일 |
|---|---|---|---|
| Claude Code | `/Users/wonjin/dev/word-spire` | `main` | 엔진·화면·채점 (CODING_PLAN 마일스톤) |
| Codex | `/Users/wonjin/dev/word-spire-story` | `story` | 스토리 설정집, 꿀벌 탑 2·3층 글 |

두 폴더는 같은 git 저장소다. 한쪽에서 한 커밋은 다른 쪽에서 바로 병합할 수 있다.

## 처음 한 번 (이미 만들어 둠)
```sh
cd /Users/wonjin/dev/word-spire
git worktree add -b story ../word-spire-story main
cd ../word-spire-story && npm install --ignore-scripts
```

## Codex 시작하기
1. Codex를 **`/Users/wonjin/dev/word-spire-story` 폴더**에서 연다. (`word-spire`가 아님)
2. 첫 지시:
   > AGENTS.md와 docs/스토리-작업지시서.md를 읽고 그대로 작업해. 끝나면 story 브랜치에 커밋하고 사용자 확인 목록을 보여 줘.
3. Codex가 `story` 브랜치에 커밋한다. GitHub에 올려 두려면 `git push -u origin story`.

## 검토하고 합치기
1. 형이 `docs/스토리.md`와 `bee-2.ts`, `bee-3.ts`를 읽고 사실과 문장을 검수한다. 고칠 것은 Codex에게 다시 시킨다.
2. 다 되면 Claude Code에게: **"story 브랜치 합쳐줘"**
   - Claude Code가 `main`에 병합하고 `npm test`·`npm run build`를 돌린다.
   - 설정집의 "데이터 칸 제안"은 형이 고른 것만 기획안·작업지시서에 반영한 뒤 구현한다(M8 탑 흐름, M11 연출).
3. 충돌이 나면 Claude Code가 풀고, 무엇을 어떻게 풀었는지 보고한다.

## 서로 건드리지 않는 범위
- **Codex**: `docs/스토리.md`, `docs/스토리-작업지시서.md`의 "질문과 답" 칸, `src/content/passages/bee-2.ts`, `bee-3.ts`, `src/content/index.ts`의 `passages` 배열만 고친다. 자세한 건 `AGENTS.md`.
- **Claude Code**: Codex가 작업하는 동안 위 파일들을 고치지 않는다.

## main이 바뀌었을 때
엔진이나 데이터 형식이 바뀌어 Codex도 최신 코드가 필요하면 Codex 폴더에서:
```sh
git merge main
```

## 컨셉 아트는?
설정집(A-5 컨셉 아트 브리프)이 나온 뒤에 시작한다. 그림 생성은 컨셉용이고, 게임에 넣는 스프라이트는 M11에서 정해진 격자 크기로 다시 만든다. 파일 이름은 적의 스프라이트 id(`drought` 등)와 같게, 위치는 `src/ui/sprites/`, 생성 프롬프트는 같은 이름의 `.prompt.txt`에 남긴다.

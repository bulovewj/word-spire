## A. 설정집 `docs/스토리.md`

### 원칙
- **이야기는 짧게.** 한 층이 5~10분이고, 읽는 시간은 본문 글에 써야 한다. 이야기 문구는 아래 분량을 넘지 않는다.
- **이야기는 게임 장치를 설명하는 데 쓴다.** 장식이 아니라 "왜 이렇게 싸우는가"의 답이다.
- 폭력 수위는 낮게. 적은 처치가 아니라 **봉인**하고, 내가 지면 "쓰러졌어"다.
- 학생 화면은 반말, 초등 5~6학년 어휘.
- 슬레이 더 스파이어의 이름·카드명·설정을 쓰지 않는다.

### 세계관이 설명해야 할 장치 (기획안 4·6장)

| 장치 | 이야기가 답해야 할 것 |
|---|---|
| 탑 = 화제 하나, 3층 | 탑마다 주제(꿀벌 등)가 다른 까닭, 층이 오를수록 글이 어려워지는 까닭 |
| 안개(▒▒로 가려진 낱말), 안개 보호막 | 낱말이 왜 가려져 있고, 가려진 동안 왜 적이 덜 맞는가 |
| 질문 공격(근거 문장을 대야 세게 맞음) | 근거를 대는 것이 왜 힘이 되는가 |
| 낱말 카드 = 방어, 덱 = "내가 아는 낱말" | 아는 낱말이 왜 나를 지켜 주는가, 안개를 걷은 낱말이 왜 덱에 들어오는가 |
| 요약 봉인(적은 요약으로만 쓰러짐) | 왜 한 문장 요약으로만 적을 봉인할 수 있는가 |
| 생각력, 확신도(확실/애매) | 주인공이 무엇을 힘으로 쓰는가, "확실"이라고 말하는 것의 무게 |

### 들어갈 항목
1. **세계관 한 쪽**: 위 표의 장치마다 1~3문장.
2. **주인공**: 이름(또는 이름 없이 "나"로 갈지 제안), 모습, 성격 3줄. 성별을 정하지 않아도 되게 쓴다.
3. **탑 "꿀벌"**: 탑 들어갈 때 소개 2~3줄, 탑 완료 마무리 2~3줄. 한 줄 40자 안팎.
4. **적 3종**: 1층은 이미 정해져 있다(**가뭄 도깨비**, 스프라이트 id `drought`). 2·3층 적을 정한다. 적마다 다음을 쓴다.
   - 이름, 스프라이트 id(영문 소문자, 예: `drought`)
   - 글 주제와의 관계: 그 층 글이 다루는 문제를 의인화한 것이면 좋다
   - 모습 묘사 3~5줄 (그림 작업에 그대로 쓴다: 실루엣, 색 2~3개, 특징 하나)
   - 등장 대사 1줄, 봉인될 때 대사 1줄
5. **컨셉 아트 브리프**: 주인공과 적 3종을 도트로 그릴 때의 설명. 지금 화면 색은 `src/styles/tokens.css`(크림 바탕, 잉크색 외곽선, 세이지·라벤더·금빛)를 기준 팔레트로 쓴다. 예전 시안은 `_archive/reading-static/assets/`에 참고용으로 있다.
6. **데이터 칸 제안**: 위 문구를 게임에 넣으려면 필요한 칸을 TypeScript 인터페이스 모양으로 제안만 한다. 예: `Tower { id, title, intro: string[], outro: string[] }`, `Enemy`에 `introLine`, `sealLine` 추가. **`types.ts`는 고치지 않는다.**
7. **글 출처**: B에서 쓴 사실마다 확인한 출처(기관·자료명·링크).

## B. 꿀벌 탑 2·3층 글 `bee-2.ts`, `bee-3.ts`

### 형식
`src/content/passages/bee-1.ts`와 똑같은 `Passage` 형식(작업지시서 1-2). 만든 뒤 `src/content/index.ts`의 `passages` 배열에 추가하고 `npm test`가 통과해야 한다(데이터 검사가 형식 오류를 잡는다).

### 내용
| | 2층 `bee-2` | 3층 `bee-3` |
|---|---|---|
| 난도 | 본 글 | 조금 어려운 글 |
| 문장 수 | 6~7 | 7~8 |
| 적 체력 `maxHp` | 45 | 55 (보스) |
| 적 공격 `pattern` | 5~9 사이 값 3개 | 5~9 사이 값 3~4개 |
| 잠긴 낱말 | 1~2개 | 1~2개 |

- **앞 층 글이 다음 층의 배경지식**이 되게 이어 쓴다(1층: 꿀벌이 줄면 밥상이 위협받는다).
- 정보글이다. **확인 가능한 사실만** 쓰고 출처를 A-7에 남긴다. 숫자·통계는 출처가 분명할 때만.
- 질문은 3개: `literal`(거기 있음) 1, `connect`(연결) 1, `author`(글쓴이와 나) 1.
  - 보기 4개. 정답이 길이·말투로 티 나지 않게(오답도 그럴듯하게).
  - `answer`는 몇 번이든 된다(화면에서 보기 순서를 섞는다).
  - `evidence`: `{ count, required, allowed }`. `count`는 학생이 고를 문장 수(화면이 "N개를 골라 봐"로 안내), `required`는 꼭 들어가야 할 문장 묶음 후보(하나만 만족하면 됨), `allowed`는 함께 골라도 되는 문장. **작업지시서 1-5 출제 원칙을 따른다.**
  - 2층 `author` 질문의 `bonusWords`는 `['bee-w1']`("위협"). 3층은 2층 잠긴 낱말 id를 쓴다.
- 잠긴 낱말: `word`는 문장에 그대로 있는 문자열. `clues`는 뜻을 짐작하게 하는 다른 문장 index. `card`는 `WordEntry` 형식(`accepts` 2~3개, `rejects`는 반대 뜻 1개 + 글자 그대로 오해 1개). id는 `bee-w2`, `bee-w3`… 기본 팩(`pack-5-6.ts`)과 겹치지 않게.
- `summary`: `models` 3~5개, `concepts` 3묶음(동의어 묶음), `minConcepts` 3, `conceptLabels`는 학생에게 "빠진 것: …"으로 보일 말, `rejects`는 세부만 쓴 요약·반대 내용 요약 3개.
- 피해·체력 균형은 신경 쓰지 않아도 된다. 시뮬레이션 검사는 M8에서 Claude Code가 한다.

## 1. 데이터 형식

### 1-1. 낱말 (`content/words/*.ts`)

```ts
interface WordEntry {
  id: string
  word: string
  kind: '관용구' | '속담' | '한자어' | '교과어' | '기타'
  meaning: string          // 대표 뜻. 틀렸을 때 보여 줌
  accepts: string[]        // 같은 뜻 다른 표현 2~3개
  rejects: string[]        // 반대 뜻 1개 + 글자 그대로 오해 1개
  example?: string         // 예문 (낱말 자리를 ○○○로 가려 힌트로 씀)
}
```

### 1-2. 글 한 편 (`content/passages/*.ts`)

```ts
type QuestionType = 'literal' | 'connect' | 'author'   // 거기 있음 / 연결 / 글쓴이와 나

interface Passage {
  id: string
  towerId: string
  floor: 1 | 2 | 3
  title: string
  enemy: { name: string; sprite: string; maxHp: number; pattern: number[]; introLine: string; sealLine: string }  // pattern: 턴별 공격값, 반복
  sentences: string[]         // 화면 번호는 1부터, 데이터 index는 0부터
  lockedWords: LockedWord[]   // 0~2개
  questions: Question[]       // 2~3개
  summary: SummarySpec
}

interface LockedWord {
  word: string                // 문장 안에 그대로 있는 문자열
  sentence: number            // 이 낱말이 있는 문장 index
  clues: number[]             // 정답 단서 문장 index (하나만 골라도 성공)
  card: WordEntry             // 성공 시 덱에 들어갈 낱말 카드
}

interface Question {
  id: string
  type: QuestionType
  prompt: string
  options: string[]           // 4개
  answer: number              // options index
  evidence: { count: number; required: number[][]; allowed?: number[] }  // 정확히 count개 + required 후보 하나를 다 포함 + 모두 (required 전체 ∪ allowed) 안이면 근거 정답
  bonusWords?: string[]       // author 전용. 이 낱말 카드를 붙이면 +4
}

interface SummarySpec {
  models: string[]            // 모범 요약 3~5개
  concepts: string[][]        // 핵심 개념. 각 배열은 동의어 묶음(하나라도 들어 있으면 그 개념 있음)
  minConcepts: number
  conceptLabels: string[]     // 빠졌을 때 보여 줄 말. concepts와 같은 순서
  rejects: string[]           // 오답 요약 앵커(세부만 쓴 것, 반대 내용)
}
```

### 1-4. 데이터 검사
`content/validate.ts`: 모든 글·낱말·탑을 앱 시작 전에(그리고 테스트에서) 검사한다. 문장 index 범위(근거 required·allowed 포함), `answer` 범위, 보기 4개, `lockedWords.word`가 해당 문장에 실제로 있는지, `conceptLabels` 길이 = `concepts` 길이, 낱말 id 중복, accepts·rejects 1개 이상, 예문에 낱말(활용형)이 그대로 있는지(가리는 건 화면), 적 introLine·sealLine, 글의 `towerId`에 맞는 탑, 근거 `count`(literal 1, connect 2 이상, 필수 묶음 ≤ count ≤ 관련 문장 수). 틀리면 어느 파일 어느 항목인지 알려 주는 오류.

### 1-5. 문항 출제 원칙
1. 근거는 **답 보기를 뒷받침하는 문장**이다. 질문에 이미 쓰인 전제나 결과를 되풀이한 문장은 근거로 요구하지 않는다(예: "꿀벌이 줄면 왜 밥상이 위협받을까?"에 "꿀벌이 줄면 밥상이 위협받는다" 문장).
2. 그럴듯한 다른 근거가 있으면 `required` 후보나 `allowed`에 넣는다. 맞게 생각한 학생이 약타를 받으면 안 된다.
3. `count`는 그 질문에 답하는 데 꼭 필요한 문장 수. `literal` 1, `connect` 2(필요하면 그 이상), `author`는 문항마다.
4. 근거가 애매하면 데이터로 땜질하지 말고 질문이나 본문을 고친다.
5. 원칙 2를 넓게 쓰지 않는다. **정답이 되는 근거 문장이 본문의 절반을 넘으면** 아무 문장이나 찍어도 맞아서 근거 찾기가 사라진다 → 직접 근거만 남긴다.
6. 정답 보기는 본문 문장을 그대로 베끼지 않고 **다른 말로** 쓴다. 낱말 맞추기로 정답을 고를 수 있으면 안 된다. 같은 글의 다른 질문 정답과도 표현이 겹치지 않게.

## 2. 채점 명세

모델: `Xenova/multilingual-e5-small`, `dtype: 'q8'`, **입력마다 앞에 `query: `를 붙인다.** `pooling: 'mean', normalize: true`. Web Worker에서만 실행.
기준값은 전부 `grading/policy.ts`에.

### 2-1. 낱말 뜻 (`grading/word.ts`)
순서대로 보고, 걸리면 그 메시지로 실패.
1. 사전 검사: "모르겠/몰라/모름/잘 모르/글쎄/ㅁㄹ/ㅇㅇ/아무거나/???"로 시작 → "짐작이라도 써 봐!" / 2글자 미만 → "조금 더 길게" / 낱말을 그대로 베낌(띄어쓰기·문장부호 무시, 낱말 포함 + 2글자 이내 추가) → "뜻을 풀어서 써 봐!"
2. `reject` = 학생 답과 그 낱말 rejects 중 최고 유사도. `own` = meaning+accepts 중 최고. `reject >= own` → "반대 뜻에 가까워!"
3. `other` = 비교 대상 낱말(기본 팩 전체 + 이 탑 글들의 `lockedWords[].card`, 자기 자신 제외) 각각의 (meaning+accepts) 최고 유사도 중 최댓값. `own - other < 0` → "다른 낱말이랑 헷갈렸나 봐."
4. `own < 0.88` → "뜻이 조금 달라."
5. 통과.
- 결과: `{ pass, own, other, reject, reason }`.
- 비교 대상 전체 뜻 벡터는 전투 시작 때 미리 계산해 캐시(키: id + 뜻 문자열).

### 2-2. 요약 (`grading/summary.ts`)
1. 길이 10~60자(공백 제외) 밖 → "한 문장으로, 너무 짧지도 길지도 않게!"
2. 핵심 개념: 각 동의어 묶음 중 하나라도 답에 들어 있으면 그 개념 있음. `minConcepts` 미만 → "빠진 것: (빠진 conceptLabels)"
3. `reject >= own`(모범 요약 vs 오답 앵커) → "글의 일부만 썼거나 내용이 달라."
4. `own < 기준값` → "핵심은 있는데 뜻이 잘 안 통해." (기준값은 M6에서 점검 화면으로 정함. 처음엔 0.86)
- 결과: `{ pass, missing: string[], own, reject, reason }`.

### 2-3. 모델이 없을 때 (간이 채점)
모델 로딩 중·실패 시. 화면 위 배지로 "의미 채점 준비 n% / 간이 채점" 표시.
- 낱말: 글자 1-gram·2-gram 코사인(0.4·0.6 가중 평균) 기준 0.42, rejects가 더 가까우면 실패.
- 요약: 1·2단계(길이, 핵심 개념)만으로 판정.

## 3. 기능 명세

### F1. 전투 화면
- 시나리오: 층에 들어가면 글, 적, 내 상태, 손패가 한 화면에 보인다.
- 화면: **본문 패널**(문장마다 번호, 잠긴 낱말은 `▒▒`), 적(도트, 체력바, **다음 공격 예고**), 나(체력바 + **받을 피해 예고 칸**, 방어), 생각력 보석 3개, 손패, 턴 끝내기.
- 데이터: 화면은 `GameState`를 그리기만 하고 action만 보낸다.

### F2. 질문 공격
- 시나리오: 질문 카드 → 질문·보기 4개 → 보기 고르기 → 본문에서 근거 문장 탭(다시 탭하면 해제) → 확실/애매 → 제출 → 정타/약타/실패 연출.
- 화면: 질문 패널이 손패 자리에 열리고 본문 문장이 탭 가능 상태가 된다. "근거 문장 N개를 골라 봐 (k/N)"로 문항의 `evidence.count`를 안내하고, N개까지만 고를 수 있다(바꾸려면 고른 문장을 다시 눌러 뺀다). 제출 버튼은 보기·근거 N개·확신도를 다 골라야 켜진다. 제출 뒤 결과에 약타·실패의 까닭을 한 줄로 보인다. **제출 전 정답 암시 금지.** 미리보기는 "정타 9 / 약타 5 / 실패 0"처럼 범위만.
- 보기 표시 순서는 전투 시작 때 `GameState.rng`로 섞어 `optionOrder`에 둔다(데이터의 `answer` 위치로 정답이 티 나지 않게). 판정은 데이터 index로 한다.
- 단서 보기(생각력 1, 애매로 틀린 뒤 1회 공짜): 질문 패널의 버튼. 누르는 순간 `useHint({ questionId })`로 생각력을 쓰고 틀린 보기 1개(rng로 고름)를 흐리게 한다. 질문당 1번, 패널을 닫았다 열어도 유지(공짜로 다시 보기 방지). 그 질문을 낼 생각력이 남아 있어야 쓸 수 있다. 쓴 기록 `GameState.hints`가 곧 "도움받음".
- 피해 계산 순서: 기본 피해 → (author 보너스 낱말 +4) → (약타면 절반, 내림) → (정타 + 확실이면 ×1.5, 반올림) → (보호막 -2, 최소 0) → 적 체력 1 하한. 확실인데 약타·실패면 적의 다음 공격 +3.
- 낱말 카드 붙이기(author 전용, 기획안 6-2): 질문 패널에 그 질문 `bonusWords`에 든 손패 낱말 카드만 "붙이기" 버튼으로 보인다. 생각력 추가 없음. 제출하면 붙인 카드는 판정과 상관없이 버린 더미로.
- action: `resolveQuestion({ questionId, option, evidence, confidence, attachedWordUid? })`, `useHint({ questionId })`

### F2-1. 손패 구성
기획안 6-1 표대로. `GameState`에 글 카드(질문·안개·요약)와 낱말 카드를 따로 둔다.
- `textCards`: `{ kind: 'question'|'fog'|'summary', refId, lockedThisTurn: boolean, retry: boolean }` — 턴 끝에 남고, 새 턴에 `lockedThisTurn=false`. `retry=true`는 F6의 "다시 보기"로 돌아온 질문(피해 절반, 도움 기록).
- 요약 봉인은 적 체력이 40% 이하가 되거나 질문 카드를 다 쓴 action 직후 `textCards`에 추가된다.
- `hand`(낱말 카드): 턴마다 2장 뽑고 턴 끝에 버린다.
- 단서 보기는 카드가 아니다. 질문 패널 안의 버튼이고 `useHint` action으로 처리한다(처음엔 `resolveQuestion`의 `usedHint`였으나, 단서를 보고 취소하면 공짜가 되는 구멍이 있어 바꿈 — 2026-10-20).

### F3. 안개 걷기
- 시나리오: 안개 걷기 카드 → "‘▒▒’의 뜻을 짐작하게 해 주는 문장을 골라 봐" → 문장 1개 탭 → 제출.
- 성공: 안개가 걷히고 "낱말 카드 획득 예정". 실패: 카드 실패.
- 잠긴 낱말이 남아 있는 동안 질문 피해 -2(보호막).
- 성공하면 그 낱말 id를 `GameState.reservedWords`에 예약(층 보상으로 덱에 — M8). 실패하면 카드가 이번 턴 잠긴다.
- action: `resolveFog({ wordIndex, sentence })`

### F4. 낱말 카드
- 시나리오: 낱말 카드 → 낱말 + "이 말의 뜻을 내 말로 써 봐" + 입력칸(엔터 제출, 한글 조합 중 엔터 무시) + 예문 보기 → 결과(발동/카드 실패, 이유, 실패면 정답 뜻, 뜻 가까움 미터).
- 통과: 방어 5.
- action: `resolveWordCard({ uid, pass, answer })` — 채점은 화면에서 `grading/word.ts` 호출 후 결과만 엔진에.

### F5. 요약 봉인
- 시나리오: 적 체력 40% 이하 또는 질문 카드를 다 씀 → 손패에 요약 봉인 카드 → "이 글을 한 문장으로 요약해 봐" + 입력칸(본문은 계속 보임) → 제출.
- 통과: 봉인 연출 + 적의 `sealLine` + 처치. 실패: 빠진 개념·이유 표시, 다음 턴 재도전.
- action: `resolveSummary({ pass, answer })`

### F6. 턴·적
- 턴 끝내기 → 낱말 카드 버림 → 적 공격(예고값 + 확신 벌) → 방어로 차감 → 새 턴(생각력 3, 방어 0, 낱말 카드 2장 뽑기).
- 뽑을 더미가 비면 버린 더미를 섞어 다시 뽑는다. 둘 다 비면 그냥 넘어간다.
- 질문 피해로 적 체력은 1 밑으로 안 내려간다.
- 질문을 다 썼는데 요약 봉인이 안 열렸으면, 요약 봉인을 열고 실패·약타였던 질문을 "다시 보기"(피해 절반, 도움 기록)로 손패에 돌려준다.

### F7. 탑 흐름·저장
- 타이틀 → 탑 선택 → 탑 `intro` 2줄 → 1층 → 보상(얻은 낱말 카드, 체력 +10) → 2층 → 3층 → 탑 `outro` 2줄 → 탑 완료.
- 탑 문구는 `content/towers/*.ts`(`Tower { id, title, intro, outro }`), 주인공·공통 문구는 `content/story.ts`. 적 등장 대사는 전투 1턴 시작 때 적 옆에.
- 내 체력은 탑 안에서 이어진다. 패배 시 "이 층 다시 하기"(층 시작 상태로).
- 매 action 후 자동 저장. 타이틀에 "이어하기".
- 구현: `engine/run.ts`의 `RunState`(층·체력·덱·층 시작 상태·전투)와 `reduceRun`(`startFloor`·`battle`·`finishFloor`·`retryFloor`). 층 보상 = 그 전투의 `reservedWords`를 덱에 + 체력 +10(최대 넘지 않음).
- 저장(`storage/store.ts`): 전투 속 글 데이터는 id만 저장하고 불러올 때 지금 데이터로 되돌린다. 형식 키는 `RUN_VERSION.STATE_VERSION` — 하나라도 바뀌면 이어하기를 숨긴다. 탑 완료 뒤 "처음으로"를 누르면 진행 저장을 지운다.

### F8. 기록·스탯
- 판정마다 기록: `{ area: 'word'|'literal'|'connect'|'author'|'summary', firstTry, correct, confidence?, helped, at }`. `literal`은 약점 판정에서 뺀다.
- 스탯 화면: 기획안 8장. 판단력 = (확실 정답률) − (애매 정답률), 각 5개 이상일 때만.
- **결과 코드 복사**: 이름(학생 입력, 기기에만 저장) + 영역별 집계 → JSON → 압축 → base64.

### F9. 교사 화면
- 타이틀 "선생님" → 결과 코드 여러 줄 붙여 넣기 → 학급 표(이름 / 영역별 정답률 / 판단력 / 약점 강조).
- 저장 안 함(새로 고치면 사라진다고 안내).

### F10. 채점 점검 화면 (개발용)
- `?dev=grading`일 때만. 낱말 또는 글 선택 → 답을 여러 줄 붙여 넣기 → 줄마다 own/other/reject, 핵심 개념, 판정, 이유를 표로.
- 목적: 형이 실제 학생 답으로 기준값을 정한다.

## 5. 엣지 케이스
- 모델 로딩 중·실패 → 2-3 간이 채점, 배지 표시.
- 저장 버전이 다름 → 이어하기 숨김. 기록(스탯)은 따로 보관해 유지.
- localStorage 사용 불가(시크릿 창 등) → 오류 없이 저장만 안 됨.
- 근거를 하나도 안 고름 → 제출 비활성.
- 결과 코드 깨짐 → 교사 화면에서 그 줄만 "읽을 수 없는 코드".
- 좁은 화면(390px) → 본문 위, 전투 아래. 본문 패널 접기/펴기.
- 첫 다운로드 중 전투 시작 → 간이 채점으로 진행, 준비되면 자동 전환.

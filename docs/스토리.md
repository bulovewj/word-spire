# 낱말탑 스토리 설정집 — 검토용 초안

스토리·글 담당: Codex · `story` 브랜치 · 2026-10-20
게임 규칙은 `docs/기획안.md` 6장을 따른다. 아래 설정은 허구이며, 정보글 본문과 분리한다.
문구와 데이터 칸은 제안이다. 이번 작업은 설정집·글 데이터까지만 작성한다.

## 1. 세계관 한 쪽

### 화제마다 다른 세 층의 탑
낱말탑은 세상에 관한 글을 모아 둔 곳이야. 한 탑에는 한 화제의 글이 세 층에 나뉘어 있고, 위층으로 갈수록 더 많은 내용을 연결해야 해.
아래층에서 읽은 내용이 다음 글을 이해하는 발판이 돼.

### 낱말 안개와 보호막
탑에 들어온 안개가 낱말을 가리고, 모양을 뭉쳐 적이 되었어. 가려진 뜻이 남아 있으면 안개가 적을 감싸서 질문의 힘을 줄여.
앞뒤 문장에서 뜻의 단서를 찾으면 그 낱말의 안개를 걷을 수 있어.

### 질문과 근거
질문에 답하면 흩어진 글줄이 빛으로 이어져 적에게 닿아. 답을 뒷받침하는 문장까지 찾으면 빛이 단단해져서 더 큰 힘을 내.
답만 맞고 근거가 부족하면 빛도 약해져.

### 내가 아는 낱말의 방어
내가 아는 낱말은 카드에 담겨 있어. 뜻을 내 말로 풀어 쓰면 카드가 펼쳐져 안개 공격을 막아 줘.
안개를 걷은 낱말은 그 층을 마쳤을 때 내 낱말 묶음에 들어와.

### 한 문장으로 봉인
질문으로 안개를 흩어도 조각들은 다시 모이려 해. 글의 중요한 내용을 한 문장으로 묶으면 조각들이 책갈피 안에 봉인돼.
적의 힘이 약해지거나 질문 카드를 다 쓰면, 요약으로 마지막 안개를 봉인할 수 있어.

### 생각력과 확신도
생각력은 한 턴에 집중해서 쓸 수 있는 힘이야. 새 턴이 오면 다시 채워지니, 어떤 카드를 쓸지 골라 봐.
정타를 내고 ‘확실’을 골랐다면 힘이 커져. ‘확실’을 골랐는데 근거가 부족하거나 답이 틀리면 안개가 흔들린 빛을 타고 다음 공격을 키워.
‘애매’를 고르면 틀려도 그 벌은 없고, 다음 단서 보기를 공짜로 쓸 수 있어.

## 2. 주인공

- 이름: 별도 이름 없이 **‘나’**로 제안해. 학생이 자기 모습으로 생각할 수 있게 성별과 나이를 정하지 않아.
- 모습: 짧은 세이지색 망토, 크림색 옷, 낱말 카드를 넣는 작은 주머니를 멘 탐험가야.
- 성격: 궁금하면 다시 읽고, 모르면 망설임을 말하고, 자기 말로 설명하려고 해.

## 3. 탑 ‘꿀벌’의 문구

입장 소개는 두 줄만 보여 준다. 전투 전에는 본문 사실이나 문항의 답을 미리 알려 주지 않는다.

> 여긴 꿀벌에 관한 글이 세 층으로 이어진 낱말탑이야.
> 네 속도로 읽고, 네가 찾은 근거로 안개 속 길을 밝혀 봐.

완료 마무리는 3층 봉인 뒤에만 두 줄로 보여 준다.

> 세 글을 이어 읽고 네 말로 묶어서 꿀벌 탑의 안개를 걷었어.
> 새로 익힌 낱말도 챙겼으니, 다음 글에서 다시 만나 보자.

## 4. 적 세 종

적은 자연현상이나 생물을 벌주는 대상이 아니라, 글을 이해하지 못하게 가리는 **허구의 안개 덩어리**다.
본문에는 적·탑·마법 이야기를 넣지 않는다. 등장 대사는 낱말 뜻이나 정답 선택의 단서가 되지 않는다.

### 1층 — 가뭄 도깨비 (`drought`)

관계: 1층에서 다루는 꿀벌의 위기를 마른 흙의 모양으로 표현한다. 실제 꿀벌 감소의 원인을 가뭄 하나로 설명하는 설정은 아니다.

- 실루엣은 낮고 둥근 흙덩이에 짧은 두 발이 달린 모습이야.
- 몸은 크림색, 그늘은 라벤더색, 작은 눈은 금빛이야.
- 몸 한가운데 갈라진 틈 하나가 눈에 띄어.
- 뿔과 이빨 대신 접힌 종이 같은 둥근 귀가 있어.

등장: “내 안개를 지나갈 수 있겠어?”
봉인: “이런, 책갈피가 닫히잖아!”

### 2층 — 빈꽃 도깨비 (`bloomgap`)

관계: 꽃이 지고 다음 꽃이 피기 전의 먹이 공백을 빈 꽃테두리로 표현한다.

- 실루엣은 꽃 모양 고리 아래로 짧은 안개 꼬리가 내려오는 모습이야.
- 고리는 세이지색, 몸은 크림색, 눈은 라벤더색이야.
- 꽃잎 테두리 안쪽이 동그랗게 비어 있는 게 특징이야.
- 손에는 무기 대신 말린 종이 끈 두 가닥이 달려 있어.

등장: “여긴 내가 지키는 층이야!”
봉인: “앗, 몸이 종이처럼 접혀!”

### 3층 — 지움 안개왕 (`erasure`)

관계: 여러 꽃가루받이 동물과 살아갈 환경을 함께 보지 못하는 문제를, 서로 다른 무늬를 지우는 안개로 표현한다.

- 실루엣은 위가 넓고 아래가 좁은 커다란 망토 모양이야.
- 망토는 라벤더색, 얼굴은 크림색, 접힌 왕관은 금빛이야.
- 망토에는 모양이 다른 작은 창 세 개가 뚫려 있어.
- 왕관 끝과 손은 둥글고, 망토 아래로 짧은 발만 보여.

등장: “마지막 층까지 왔구나. 나를 지나가 봐!”
봉인: “내 안개가 한 장으로 접히다니!”

공통 패배 문구 제안: “쓰러졌어. 이 층부터 다시 도전해 봐.” 승리는 ‘봉인했어’로 표현한다.

## 5. 컨셉 아트 브리프

기준은 `src/styles/tokens.css`의 밝은 종이 화면이다. 배경 `#f5eedb`, 패널 `#fffaf0`, 외곽선 `#2f2a3d`, 세이지 `#6faa76`, 라벤더 `#7a7393`, 금빛 `#a8741a`를 사용한다.
각 인물은 잉크색 외곽선에 본색 2~3개만 쓴다. 무지개 효과·반투명 흐림보다 또렷한 픽셀 덩어리로 그린다.
크림 바탕 위에서도 실루엣이 구분되게 하고, 글이나 낱말 정답을 그림 안에 쓰지 않는다.
아래 격자는 컨셉 제안이다. 실제 게임 격자와 파일 규격은 M11 담당자가 정한다.

봉인 공통 연출: 잉크색 몸이 종이 조각처럼 접혀 작은 책갈피에 들어간다. 피·상처·무기 타격은 없다.
‘나’의 패배는 무릎을 굽히고 카드를 내려놓는 정도로 표현한다.
옛 자료는 `_archive/reading-static/assets/`를 구도 참고로만 삼는다. 이번 산출물에는 그림 파일을 만들지 않았다.

## 6. 데이터 칸 제안

아래는 사용자 검토 뒤 Claude Code가 반영할 후보이며, 현재 `types.ts`에는 추가하지 않았다.

```ts
interface TowerStory {
  id: string                 // 'bee'; Passage.towerId와 연결
  title: string              // '꿀벌'
  intro: string[]            // 입장 때만 2줄
  outro: string[]            // 탑 완료 뒤에만 2줄
}

interface EnemyStory {
  sprite: string             // 기존 Enemy.sprite와 연결
  introLine: string          // 층 진입 때 1줄
  sealLine: string           // 봉인 성공 뒤 1줄
}

interface PlayerStory {
  displayName: string        // '나'; 학생 이름을 요구하지 않음
  sprite: string             // 'reader' 제안
  defeatLine: string         // '쓰러졌어. 이 층부터 다시 도전해 봐.'
}
```

설정 데이터는 본문과 별도 묶음으로 두고, 기존 `Enemy`에는 문구를 중복 저장하지 않는 안을 제안한다.
초상 묘사·출처·검수 메모는 문서에만 둔다. 새 게임 규칙이나 실행 중 AI 호출은 필요 없다.

문항은 각 층 `literal`·`connect`·`author` 한 개씩이다. 정답 index는 2층 1·3·2, 3층 0·1·3으로 분산했고, 보기 길이와 문장 끝맺음을 맞췄다.
연결 문항의 최소 근거는 2층 1+3번(먹이의 출처+개화 공백), 3층 3+7번(여러 종류의 역할+살 곳 소실)이다. 각각 두 문장의 연결이 필요하다.
3층 7번의 ‘이런 곳’은 5~6번의 생활 공간을 받는다. 이를 함께 고르는 조합도 허용했다. `evidence`는 지정 조합과 정확히 같아야 하므로 문장을 더 고른 답은 형식 검사만으로 적절성을 판단할 수 없다.
2층 보너스는 1층 ‘위협’(`bee-w1`), 3층은 2층 ‘공급’(`bee-w2`)으로 앞 층 보상을 잇는다.
요약은 모범 4개·핵심 개념 3묶음·오답 앵커 3개씩이다. 개념의 포함만으로 문장의 인과나 부정을 판단할 수 없어, 실제 학생 답 검수는 의미 채점 점검 화면에서도 필요하다.

검증(요청 1 반영 후): `npm test` 65개 통과, `npm run build` 통과. 별도 데이터 점검으로 층별 개수·수치, 이전 층 보너스 id, 단서 문장 분리, 모범 요약의 10~60자와 핵심 개념 포함, 파일·문구 분량을 확인했다.
